# Upgrading to JFrame 1.9.0 — HTTP Client TLS

**Applies to:** JFrame 1.9.0 (`jframe-spring-otlp`)

`HttpClientSSLFactory` now takes a `TlsOptions` argument instead of a boolean flag plus trust store parameters.

Other 1.9.0 changes (credential masking, `ErrorResponseWriter`, Quarkus OTLP config) are in [Hardening](./1.9.0-hardening.md).

---

## 1. Will it still compile?

**No**, if you call `createRequestFactory` directly. The five-argument overload is removed:

```java
// Removed
createRequestFactory(boolean useSecureConnection, String trustStorePath, String trustStorePassword,
                     int connectTimeoutSeconds, int readTimeoutSeconds)

// New
createRequestFactory(TlsOptions options, int connectTimeoutSeconds, int readTimeoutSeconds)
```

`TlsOptions` lives in `io.github.jframe.factory`.

| Factory | Trust behaviour |
|---------|-----------------|
| `TlsOptions.defaultTrustStore()` | JVM `cacerts`; certificate and hostname verification. **Recommended** for public-CA endpoints |
| `TlsOptions.customTrustStore(path, password)` | Your own trust store file |
| `TlsOptions.sslBundle(SslBundle)` | A Spring Boot SSL bundle (`spring.ssl.bundle.*`) |
| `TlsOptions.trustAll()` | Accepts any certificate. Logs a `WARN`. Dev and self-signed only |

Null arguments throw `NullPointerException`; a blank trust store path throws `IllegalArgumentException`. A TLS setup failure (e.g. missing trust store) throws `IllegalStateException` with the cause; it was `HttpException` (500). `getTrustAllManager()` is now private.

---

## 2. Migrate your calls

```java
// Before: custom trust store
createRequestFactory(true, path, password, connect, read);
// After
createRequestFactory(TlsOptions.customTrustStore(path, password), connect, read);

// Before: verification off
createRequestFactory(false, null, null, connect, read);
// After: same behaviour
createRequestFactory(TlsOptions.trustAll(), connect, read);
// After: preferred for public-CA endpoints
createRequestFactory(TlsOptions.defaultTrustStore(), connect, read);
```

Avoid `trustAll()` outside local development. It allows man-in-the-middle attacks: bearer tokens can leak and OIDC endpoints can be swapped.

---

## 3. Behaviour change

`connectTimeoutSeconds` now also sets the socket connect timeout. Previously it only limited the wait for a pooled connection. Connections to unreachable hosts now fail after that many seconds.
