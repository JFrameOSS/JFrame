# Upgrading to JFrame 1.7.0 — Strict Search Input

**Applies to:** JFrame 1.7.0

`AbstractSortSearchMetaData` (Spring) and `AbstractPanacheSearchMetaData` (Quarkus) are now **strict by default** across sorting, paging, and filtering. Previously-silent failures now produce `400` responses.

---

## 1. Will it still compile?

**No** — several breaking API changes:

| Change | What to do |
|--------|-----------|
| `toSort()` / `toPageable()` / `resolveSort()` may throw `InvalidSortException` | Catch it, or let jFrame's handler render the 400 |
| `toPageable()` / `resolveSort()` may throw `InvalidPageException` | Catch it, or let jFrame's handler render the 400 |
| `toSearchCriteria()` may throw `InvalidSearchException` | Catch it, or let jFrame's handler render the 400 |
| `SpringPageAdapter.toPageResource(Page, AppliedSort)` overload added | No action — existing calls still compile |
| `PageResource` gained a nullable `appliedSort` field | No action if you use Lombok-generated constructors |

---

## 2. Will it still behave the same?

No. All three input dimensions — sort, paging, and filtering — are now strictly validated.

### 2.1 Unknown or non-sortable fields now throw

| Request | Before 1.7.0 | After 1.7.0 |
|---------|--------------|-------------|
| Field not registered | WARN log, field discarded | **`InvalidSortException` (400)** |
| Field registered as non-sortable | WARN log, field discarded | **`InvalidSortException` (400)** |
| Null or blank direction | treated as ascending or discarded | **`InvalidSortException` (400)** |
| Direction not `ASC`/`DESC` | treated as ascending or discarded | **`InvalidSortException` (400)** |

Find tests relying on the old silent discard behaviour:

```bash
grep -rn "shouldDiscard\|non-sortable\|Discard.*sort\|warn.*sort" \
  --include="*.java" src/test/
```

### 2.2 Default sort applied when request is empty

When `sortOrder` is `null` or empty, `resolveSort()` applies `defaultSort()` (default: empty list → unsorted). Implement `defaultSort()` to guarantee a stable server-side order:

```java
@Override
protected List<SortableColumn> defaultSort() {
    return List.of(new SortableColumn("createdAt", "DESC"));
}
```

`AppliedSort.isDefault()` is `true` when the default was applied.

### 2.3 Tiebreaker appended automatically

`tiebreakerProperty()` returns `"id"` by default. The tiebreaker column is appended `ASC` to every resolved sort unless already present. Override to change the column or return `null` to disable:

```java
@Override
protected String tiebreakerProperty() {
    return null; // no tiebreaker
}
```

### 2.4 Invalid paging now throws

| Request | Before 1.7.0 | After 1.7.0 |
|---------|--------------|-------------|
| `pageNumber < 0` | Accepted or NPE | **`InvalidPageException` (400)** |
| `pageSize <= 0` | Used as-is (Spring: 500) | Falls back to `getDefaultPageSize()` (20) |
| Quarkus: offset overflow | Silently wrong results / negative offset | **`InvalidPageException` (400)** |

### 2.5 Fuzzy search no longer treats `%`, `_`, `\` as wildcards

`FUZZY_TEXT`, `MULTI_FUZZY`, and `MULTI_COLUMN_FUZZY` now escape `%`, `_`, and `\` in user-supplied terms before passing them to `LIKE … ESCAPE '\'`. Previously, a user searching for `"_"` matched every row. Lowercasing uses `Locale.ROOT` for locale-independent results.

> **Tests asserting that `%` or `_` in a search term matches everything must be updated to expect literal matching.**

### 2.6 Unknown or invalid filter fields now throw

`toSearchCriteria()` (called from `toSearchSpecification()` and `PagedSearchingService.searchPage()`) is now strict:

| Request | Before 1.7.0 | After 1.7.0 |
|---------|--------------|-------------|
| Unknown `fieldName` | INFO log, filter silently dropped | **`InvalidSearchException` (400)** |
| `NUMERIC` / `MULTI_NUMERIC` — non-integer value | `NumericField` → 0; `MultiNumericField` → entry skipped | **`InvalidSearchException` (400)** |
| `ENUM` — unknown constant (case-sensitive) | `EnumField` → `null` filter | **`InvalidSearchException` (400)** |
| `MULTI_ENUM` — unknown constant | Entry passed as `null` | **`InvalidSearchException` (400)** |
| `BOOLEAN` — not `true` / `false` | Coerced to `false` | **`InvalidSearchException` (400)** |
| `DATE` — non-ISO instant | `DateTimeParseException` → 500 | **`InvalidSearchException` (400)** |
| Null / blank value | No filter | No filter (unchanged) |

> **Case sensitivity:** Enum constants must match exactly. `"active"` is rejected if the enum constant is `ACTIVE`.

Find tests that rely on the old silent-drop or coerce behaviour:

```bash
grep -rn "shouldIgnore\|silently.*drop\|unknown.*field\|textValue.*\"[0-9]" \
  --include="*.java" src/test/
# Also check for numeric coercion tests:
grep -rn "NumericField\|MultiNumericField\|EnumField\|BooleanField\|DateField" \
  --include="*Test.java" src/test/
```

### 2.7 `PagedSearchingService.searchPage` now validates sort and page

Both overloads of `PagedSearchingService.searchPage()` now call `metaData.resolveSort(input)` internally. Previously the second overload called `PageRequest.of` directly, bypassing sort validation and max-page-size enforcement. Side effects:

- Default sort, tiebreaker, default page size, and max page size all apply.
- `pageSize == 0` no longer causes a 500; it falls back to `getDefaultPageSize()`.
- Sort and page errors surface as `InvalidSortException` / `InvalidPageException` (400).

### 2.8 Quarkus sort parity with Spring

`PanacheSearchRepository` now applies the same ordering rules as Spring:

| Behaviour | Before 1.7.0 | After 1.7.0 |
|-----------|--------------|-------------|
| String columns | Default DB collation | `lower()` — case-insensitive |
| Nulls position | DB default (usually first) | NULLS LAST on every column |
| Dotted nested paths (e.g. `"tenant.name"`) | Not supported | LEFT join, then sort |

> **Existing Quarkus query results may change order.** Review any tests that assert on the order of returned records.

## 3. New API

### jframe-core

| Type | Description |
|------|-------------|
| `AppliedSort(field, direction, isDefault)` | Describes the resolved sort. `isDefault` serialises as `"isDefault"` in JSON. |
| `PageResource.appliedSort` | Nullable; omitted from JSON when `null`. |
| `InvalidSortException(rejectedField, sortableFields)` | Extends `HttpException`, 400, `JFrameErrorCode.INVALID_SORT`. |
| `InvalidSearchException(rejectedField, rejectedValue, searchableFields)` | Extends `HttpException`, 400, `JFrameErrorCode.INVALID_SEARCH`. Keeps the parse failure as the exception cause. |
| `InvalidPageException(rejectedParameter, rejectedValue)` | Extends `HttpException`, 400, `JFrameErrorCode.INVALID_PAGE`. |
| `InvalidFieldValueException(message, rejectedValue)` | Extends `IllegalArgumentException`. Thrown by field types; caught and re-wrapped as `InvalidSearchException`. Message contains the value truncated to 100 characters. |
| `AbstractSearchMetaData` | New framework-agnostic base in `io.github.jframe.datasource.search.model`. `AbstractSortSearchMetaData` (Spring) and `AbstractPanacheSearchMetaData` (Quarkus) extend it. Consumer API unchanged. |
| `JFrameErrorCode.INVALID_SORT` | Fixed error code `"INVALID_SORT"`. |
| `JFrameErrorCode.INVALID_SEARCH` | Fixed error code `"INVALID_SEARCH"`. |
| `JFrameErrorCode.INVALID_PAGE` | Fixed error code `"INVALID_PAGE"`. |

### jframe-spring-jpa

| Type / method | Description |
|---------------|-------------|
| `AbstractSortSearchMetaData.resolveSort(SortablePageInput)` | Returns `ResolvedSort` with pageable, `AppliedSort`, columns, virtual flag. Validates sort and page. |
| `AbstractSortSearchMetaData.toSearchCriteria(List<SearchInput>)` | Now throws `InvalidSearchException` for unknown fields or invalid values. |
| `AbstractSortSearchMetaData.getSearchableFields()` | Returns the registered searchable field names. |
| `AbstractSortSearchMetaData.getDefaultPageSize()` | Returns `20` (default). Override to change. |
| `AbstractSortSearchMetaData.defaultSort()` | Override to supply a default column order when client sends none. |
| `AbstractSortSearchMetaData.tiebreakerProperty()` | Override to change or disable the tiebreaker. Default: `"id"`. |
| `AbstractSortSearchMetaData.virtualSortFields()` | Override to declare virtual fields (no DB column; consumer orders). |
| `AbstractSortSearchMetaData.getAllowedSortFields()` | Returns sortable + virtual fields. |
| `AbstractSortSearchMetaData.rejectAnySort(List)` | Static helper for fixed-order endpoints. Throws if list is non-empty. |
| `SpringPageAdapter.toPageResource(Page, AppliedSort)` | Overload that sets `appliedSort` on the returned `PageResource`. |
| `PageMapper.toPageResource(Page, AppliedSort)` | Overload for mapper subclasses. |
| `ResolvedSort` | Class: `pageable`, `appliedSort`, `columns`, `isVirtual`. |

### jframe-quarkus-jpa

Same contract via `AbstractPanacheSearchMetaData.resolveSort(SortablePageInput)` → `PanacheResolvedSort`.

| Type / method | Description |
|---------------|-------------|
| `AbstractPanacheSearchMetaData.resolveSort(SortablePageInput)` | Returns `PanacheResolvedSort`. Validates sort and page. |
| `AbstractPanacheSearchMetaData.toSearchCriteria(List<SearchInput>)` | Now throws `InvalidSearchException` for unknown fields or invalid values. |
| `AbstractPanacheSearchMetaData.getSearchableFields()` | Returns the registered searchable field names. |
| `PanacheResolvedSort` | Class: `page`, `sort`, `appliedSort`, `columns`, `isVirtual`. |
| `QuarkusPageAdapter.toPageResource(..., AppliedSort)` | Overload that sets `appliedSort`. |
| `QuarkusPageMapper.map(..., AppliedSort)` | Overload for mapper subclasses. |

### Error response bodies

**`InvalidSortException`** (`INVALID_SORT`):

```json
{
  "errorCode": "INVALID_SORT",
  "errorReason": "Invalid sort field or direction",
  "rejectedField": "unknownField",
  "sortableFields": ["name", "createdAt", "id"]
}
```

**`InvalidSearchException`** (`INVALID_SEARCH`):

```json
{
  "errorCode": "INVALID_SEARCH",
  "errorReason": "Invalid search field or value",
  "rejectedField": "status",
  "rejectedValue": "UNKNOWNN",
  "searchableFields": ["status", "name", "createdAt"]
}
```

> `rejectedValue` is truncated to 100 characters. It is `null` when the field itself is unknown (as opposed to an invalid value).

**`InvalidPageException`** (`INVALID_PAGE`):

```json
{
  "errorCode": "INVALID_PAGE",
  "errorReason": "Invalid page number or size",
  "rejectedParameter": "pageNumber",
  "rejectedValue": -1
}
```

Both Spring (`DefaultExceptionResponseFactory`) and Quarkus (`DefaultErrorResponseFactory` + `InvalidSearchExceptionMapper` / `InvalidPageExceptionMapper`) handle all three automatically.

## 4. Migration steps

1. **Remove lenient-sort tests** — tests asserting on the old WARN log or the silent-discard result must be updated to expect `InvalidSortException`.
2. **Update filter tests** — tests relying on unknown fields being dropped, numeric coercion, or enum-to-null behaviour must be updated to expect `InvalidSearchException`.
3. **Update fuzzy search tests** — tests expecting `%` or `_` in a user term to act as wildcards must be updated; they now match literally.
4. **Implement `defaultSort()`** — if your endpoint must return a stable order when the client omits `sortOrder`, override this method.
5. **Call `resolveSort()`** instead of `toPageable()` when you need the `AppliedSort` to include in the response.
6. **Pass `appliedSort` to `SpringPageAdapter` / `QuarkusPageAdapter`** overload to expose it in `PageResource.appliedSort`.
7. **Override `tiebreakerProperty()`** if `"id"` is not the right column, or return `null` to disable.
8. **Review Quarkus result ordering** — case-insensitive sort and NULLS LAST may change the order of existing results.
9. **Declare virtual fields** via `virtualSortFields()` for fields that cannot be delegated to the DB.

---

## Checklist

- [ ] Update or remove tests that assert on the old WARN log or silent-discard sort behaviour
- [ ] Update or remove tests that assert on dropped / coerced filter values (numeric, enum, boolean, date)
- [ ] Update fuzzy search tests that relied on `%` or `_` acting as wildcards — they now match literally
- [ ] Fix or remove tests that send `pageNumber < 0` — now a 400
- [ ] Implement `defaultSort()` where stable order matters
- [ ] Switch `toPageable()` call sites to `resolveSort()` if you need `AppliedSort`
- [ ] Use `SpringPageAdapter.toPageResource(page, resolvedSort.getAppliedSort())` (or Quarkus equivalent)
- [ ] Review `tiebreakerProperty()` — default is `"id"` (ascending)
- [ ] Declare virtual sort fields via `virtualSortFields()` if applicable
- [ ] Review Quarkus integration tests for order-sensitive assertions (sort now uses `lower()` + NULLS LAST)
