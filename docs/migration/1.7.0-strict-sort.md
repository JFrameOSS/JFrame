# Upgrading to JFrame 1.7.0 — Strict Sort Contract

**Applies to:** JFrame 1.7.0

`AbstractSortSearchMetaData` (Spring) and `AbstractPanacheSearchMetaData` (Quarkus) are now **strict by default**. Unknown fields and invalid directions throw `InvalidSortException` (400) instead of being silently discarded.

---

## 1. Will it still compile?

**No** — three breaking API changes:

| Change | What to do |
|--------|-----------|
| `toSort()` / `toPageable()` may now throw `InvalidSortException` | Catch it, or let jFrame's handler render the 400 |
| `SpringPageAdapter.toPageResource(Page)` signature unchanged; new overload `toPageResource(Page, AppliedSort)` added | No action — existing calls still compile |
| `PageResource` gained a nullable `appliedSort` field | No action if you use Lombok-generated constructors |

---

## 2. Will it still behave the same?

No. The behaviour of `toSort()` / `toPageable()` changed.

### 2.1 Unknown or non-sortable fields now throw

| Request | Before 1.7.0 | After 1.7.0 |
|---------|--------------|-------------|
| Field not registered | WARN log, field discarded | **`InvalidSortException` (400)** |
| Field registered as non-sortable | WARN log, field discarded | **`InvalidSortException` (400)** |
| Null or blank direction | treated as ascending or discarded | **`InvalidSortException` (400)** |
| Direction not `ASC`/`DESC` | treated as ascending or discarded | **`InvalidSortException` (400)** |

Find tests relying on the old silent discard behaviour:

```bash
grep -rn "shouldDiscard\|non-sortable\|Discard.*sort\|warn.*sort" \
  --include="*.java" src/test/
```

### 2.2 Default sort applied when request is empty

When `sortOrder` is `null` or empty, `resolveSort()` applies `defaultSort()` (default: empty list → unsorted). Implement `defaultSort()` to guarantee a stable server-side order:

```java
@Override
protected List<SortableColumn> defaultSort() {
    return List.of(new SortableColumn("createdAt", "DESC"));
}
```

`AppliedSort.isDefault()` is `true` when the default was applied.

### 2.3 Tiebreaker appended automatically

`tiebreakerProperty()` returns `"id"` by default. The tiebreaker column is appended `ASC` to every resolved sort unless already present. Override to change the column or return `null` to disable:

```java
@Override
protected String tiebreakerProperty() {
    return null; // no tiebreaker
}
```

## 3. New API

### jframe-core

| Type | Description |
|------|-------------|
| `AppliedSort(field, direction, isDefault)` | Class describing the resolved sort. `isDefault` serialises as `"isDefault"` in JSON. |
| `PageResource.appliedSort` | Nullable field; omitted from JSON when `null`. |
| `InvalidSortException(rejectedField, sortableFields)` | Extends `HttpException`, 400. |
| `JFrameErrorCode.INVALID_SORT` | Fixed error code `"INVALID_SORT"`. |

### jframe-spring-jpa

| Type / method | Description |
|---------------|-------------|
| `AbstractSortSearchMetaData.resolveSort(SortablePageInput)` | Returns `ResolvedSort` with pageable, `AppliedSort`, columns, virtual flag. |
| `AbstractSortSearchMetaData.defaultSort()` | Override to supply a default column order. |
| `AbstractSortSearchMetaData.tiebreakerProperty()` | Override to change or disable the tiebreaker. Default: `"id"`. |
| `AbstractSortSearchMetaData.virtualSortFields()` | Override to declare virtual fields (no DB column; consumer orders). |
| `AbstractSortSearchMetaData.getAllowedSortFields()` | Returns sortable + virtual fields. |
| `AbstractSortSearchMetaData.rejectAnySort(List)` | Static helper for fixed-order endpoints. Throws if list is non-empty. |
| `SpringPageAdapter.toPageResource(Page, AppliedSort)` | Overload that sets `appliedSort` on the returned `PageResource`. |
| `PageMapper.toPageResource(Page, AppliedSort)` | Overload for mapper subclasses. |
| `ResolvedSort` | Class: `pageable`, `appliedSort`, `columns`, `isVirtual`. |

### jframe-quarkus-jpa

Same contract via `AbstractPanacheSearchMetaData.resolveSort(SortablePageInput)` → `PanacheResolvedSort`.

| Type / method | Description |
|---------------|-------------|
| `PanacheResolvedSort` | Class: `page`, `sort`, `appliedSort`, `columns`, `isVirtual`. |
| `QuarkusPageAdapter.toPageResource(..., AppliedSort)` | Overload that sets `appliedSort`. |
| `QuarkusPageMapper.map(..., AppliedSort)` | Overload for mapper subclasses. |

### Error response

`InvalidSortException` produces a body with `rejectedField` and `sortableFields`:

```json
{
  "errorCode": "INVALID_SORT",
  "errorReason": "Invalid sort field or direction",
  "rejectedField": "unknownField",
  "sortableFields": ["name", "createdAt", "id"]
}
```

Both Spring (`DefaultExceptionResponseFactory`) and Quarkus (`InvalidSortExceptionMapper`) handle this automatically.

---

## 4. Migration steps

1. **Remove lenient-sort tests** — tests asserting on the old WARN log or the silent-discard result must be updated to expect `InvalidSortException`.
2. **Implement `defaultSort()`** — if your endpoint must return a stable order when the client omits `sortOrder`, override this method.
3. **Call `resolveSort()`** instead of `toPageable()` when you need the `AppliedSort` to include in the response.
4. **Pass `appliedSort` to `SpringPageAdapter` / `QuarkusPageAdapter`** overload to expose it in `PageResource.appliedSort`.
5. **Override `tiebreakerProperty()`** if `"id"` is not the right column, or return `null` to disable.
6. **Declare virtual fields** via `virtualSortFields()` for fields that cannot be delegated to the DB (e.g. computed or Elasticsearch fields).

---

## Checklist

- [ ] Update or remove tests that assert on the old WARN log or silent-discard behaviour
- [ ] Implement `defaultSort()` where stable order matters
- [ ] Switch `toPageable()` call sites to `resolveSort()` if you need `AppliedSort`
- [ ] Use `SpringPageAdapter.toPageResource(page, resolvedSort.getAppliedSort())` (or Quarkus equivalent)
- [ ] Review `tiebreakerProperty()` — default is `"id"` (ascending)
- [ ] Declare virtual sort fields via `virtualSortFields()` if applicable
