# Upgrading to JFrame 1.9.0 — Hardening

**Applies to:** JFrame 1.9.0 (`jframe-core`, `jframe-spring-core`, `jframe-spring-jpa`, `jframe-spring-otlp`, `jframe-quarkus-core`, `jframe-quarkus-otlp`)

Credentials are no longer logged, a few auto-configuration pitfalls are closed, and Quarkus OTLP configuration is now validated at startup. For the TLS API change see [HTTP Client TLS](./1.9.0-http-client-tls.md).

---

## 1. Will it still compile?

| Change | Breaks compile? | Who is affected |
|--------|-----------------|-----------------|
| `ErrorResponseWriter.write(..., Response.Status, String, String)` removed | **Yes** | Spring security filters / handlers calling the loose-value overload |
| `HttpLogger.logRequest` / `logResponse` take a `PasswordMasker` | **Yes** | Spring code calling `HttpLogger` directly |
| `DatasourceProxyConfiguration` is `final` and no longer a `BeanPostProcessor` | **Yes** | Code that extends or injects it as a `BeanPostProcessor` |
| `OutboundLoggingFilter` constructor gained a `PasswordMasker` | **Yes** | Quarkus code that calls `new OutboundLoggingFilter(...)` |
| Quarkus `OpenTelemetryConfig` is an interface | **Yes** | Code that subclasses, `new`s or mocks it as a class |
| Everything else | No | Behaviour only — see the sections below |

---

## 2. Spring: `ErrorResponseWriter`

The overload deprecated in 1.8.0 is removed:

```java
// Removed
ErrorResponseWriter.write(request, response, Response.Status status, String errorCode, String errorReason)

// New
ErrorResponseWriter.write(request, response, ApiError error)
ErrorResponseWriter.write(request, response, HttpException exception)
```

Pass an `ApiError` (for example a `JFrameErrorCode` or your own domain enum) or an `HttpException`:

```java
// Before
ErrorResponseWriter.write(request, response, Response.Status.FORBIDDEN, "ACCESS_DENIED", "Nope");

// After
ErrorResponseWriter.write(request, response, JFrameErrorCode.FORBIDDEN);
// or
ErrorResponseWriter.write(request, response, new HttpException(JFrameErrorCode.FORBIDDEN));
```

## 3. Spring JPA: `DatasourceProxyConfiguration`

The class is now `final`, has a private constructor and is no longer a `BeanPostProcessor` itself. The post-processor that wraps every `DataSource` in a `ProxyDataSource` is a `static` `@Bean` method.

- Do not extend `DatasourceProxyConfiguration` or inject it as a `BeanPostProcessor`.
- Wrapping behaviour is unchanged by default.

New opt-out:

```yaml
jframe:
  datasource:
    proxy:
      enabled: false   # default: true
```

When `false`, `DataSource` beans are left untouched and SQL statements are no longer logged by jFrame.

## 4. Spring OTLP

### `tracer` bean backs off

The auto-configured `tracer` bean is now `@ConditionalOnMissingBean(Tracer.class)`. If your application defines its own `io.opentelemetry.api.trace.Tracer` bean, jFrame no longer registers a second one.

### `HttpLogger` signature

```java
// Before
HttpLogger.logRequest(method, uri, headers);
HttpLogger.logResponse(statusCode, headers, body);

// After
HttpLogger.logRequest(method, uri, headers, passwordMasker);
HttpLogger.logResponse(statusCode, headers, body, passwordMasker);
```

Inject the `PasswordMasker` bean. `HttpLogger.isEnabled()` is new and returns `true` when DEBUG is on for the logger.

### Response body only buffered at DEBUG

The blocking `RestClient`/`RestTemplate` interceptor from `HttpFilter` used to buffer every response body so it could be logged. It now buffers only when `HttpLogger` DEBUG logging is enabled. With DEBUG off the original response is returned untouched, so large or streaming bodies are no longer held in memory.

The reactive `WebClient` filter now returns a response whose body can still be read after logging.

## 5. Outbound logging masks credential headers (Spring and Quarkus)

Outbound request and response logging (`HttpLogger` on Spring, `OutboundLoggingFilter` on Quarkus) now logs these header values as `***`:

- `Authorization`
- `Proxy-Authorization`
- `Cookie`
- `Set-Cookie`
- any header whose name **contains** an entry of the configured fields-to-mask list (case-insensitive), e.g. `X-Api-Password` when `password` is configured

Other header values still pass through the password masker, so embedded `password=...` style values are masked as before.

**What to check:** log-based assertions, dashboards or alerts that read these headers will now see `***`.

### Quarkus `OutboundLoggingFilter`

The constructor gained a `PasswordMasker`:

```java
// Before
new OutboundLoggingFilter(loggingConfig, filterConfig)

// After
new OutboundLoggingFilter(loggingConfig, filterConfig, passwordMasker)
```

CDI injection is unchanged. Only code that instantiates the filter by hand (typically unit tests) needs updating.

The header log format also changed: headers are logged as a key-sorted map with multiple values joined by `", "`.

```text
# Before
[EXTERNAL] Outbound request is: GET https://api.example.com/x {Accept=[application/json, text/plain], Authorization=[Bearer abc]}

# After
[EXTERNAL] Outbound request is: GET https://api.example.com/x {Accept=application/json, text/plain, Authorization=***}
```

## 6. Logging fixes you may notice

No code changes needed, but log output differs:

| Area | Change |
|------|--------|
| SQL logging suppression | `SqlStatementLogging.suppress(true)` now actually suppresses query logging. Previously statements were still logged. |
| Nested suppression | Closing an inner `SqlStatementLogging` / `HttpRequestLogging` suppression restores the **outer** state instead of clearing it. |
| Password masker | Fixes for an escaped backslash before the closing quote, truncated or unterminated values, input ending right after the key, and Unicode case folding. Values that used to leak into logs, or crash masking, are now masked. |
| `AntStylePathMatcher` | Linear-time matching; pathological patterns no longer cause catastrophic backtracking. Match results are unchanged. |

## 7. Quarkus OTLP

### `OpenTelemetryConfig` is a `@ConfigMapping` interface

`OpenTelemetryConfig` was an `@ApplicationScoped` class that read MicroProfile Config lazily. It is now a SmallRye `@ConfigMapping(prefix = "jframe.otlp")` interface bound by Quarkus. The accessors and defaults are unchanged.

```java
// Unchanged: injection
@Inject
OpenTelemetryConfig config;

// No longer compiles / works
class MyConfig extends OpenTelemetryConfig { ... }
new OpenTelemetryConfig();
```

In unit tests, mock it as an interface (`Mockito.mock(OpenTelemetryConfig.class)`) or use `SmallRyeConfigBuilder` with `.withMapping(OpenTelemetryConfig.class)`.

### Malformed values fail at startup

Values are validated when the application starts, not on first use. These now fail fast:

```properties
jframe.otlp.sampling-rate=high      # not a number
jframe.otlp.traces.enabled=maybe    # not a boolean
```

Fix or remove such values before upgrading. Properties and defaults are otherwise unchanged (`jframe.otlp.disabled` still defaults to `true`).

### Quarkus extensions are now transitive

`jframe-quarkus-otlp` declares `quarkus-arc`, `quarkus-core` and `quarkus-opentelemetry` as `api` dependencies (they were `compileOnly`), and `jframe-quarkus-otlp-deployment` adds the matching `quarkus-opentelemetry-deployment`. You no longer need to declare `quarkus-opentelemetry` yourself:

```kotlin
dependencies {
    implementation("io.github.jframeoss:jframe-quarkus-otlp:1.9.0")
    // implementation("io.quarkus:quarkus-opentelemetry")  // now redundant, safe to remove
}
```

Keeping an explicit declaration is harmless. `quarkus-security` stays optional.
