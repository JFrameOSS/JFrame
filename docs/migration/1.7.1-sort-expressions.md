# Upgrading to JFrame 1.7.1 — Sort Expressions

**Applies to:** JFrame 1.7.1

Virtual sort keys can now be ordered by the framework, and the tiebreaker supports several columns.

---

## 1. Will it still compile?

**Mostly.** One call becomes ambiguous:

`PageMapper` gained `toPageResource(Page<S>, ResolvedSort)`. A literal `null` second argument no longer compiles — cast it:

```java
// Before
mapper.toPageResource(page, null);
// After
mapper.toPageResource(page, (AppliedSort) null);
```

---

## 2. Behaviour changes

### `isVirtual` is true when any column is virtual

Previously only the leading sort column was checked. Now `ResolvedSort.isVirtual()` is `true` when **any** requested column is virtual, so the `Pageable` is unsorted in that case too. `appliedSort` still reflects the leading column.

### Composite tiebreaker

`tiebreaker()` returns a list of columns, each with its own direction. The default is `[tiebreakerProperty() ASC]`, so existing `tiebreakerProperty()` overrides keep working. Applies to Spring and Quarkus.

```java
@Override
protected List<SortableColumn> tiebreaker() {
    return List.of(new SortableColumn("createdAt", "DESC"), new SortableColumn("id", "ASC"));
}
```

---

## 3. Replace hand-rolled virtual ordering (Spring)

If you ordered virtual sort keys yourself (custom `Specification` calling `query.orderBy(...)`), register the expression instead and use `toSearchSpecification(input)`:

```java
addSortExpression("owner", (root, query, cb) -> List.of(root.get("owner").get("lastName")));
```

- Registered keys are virtual automatically; no need to list them in `virtualSortFields()`.
- `toSearchSpecification(input)` orders by the resolved sort (nulls last, `String` case-insensitive) plus `tiebreaker()`, and skips count queries.
- Remove your own `orderBy` call — the query would otherwise be ordered twice.
